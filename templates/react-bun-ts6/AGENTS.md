# Agent instructions

Confirm the repository, branch, existing changes, project standards, task authorization, scope, and unique writer before editing. Preserve other people's work. Apply the task's authorization to installations, network access, dependency and license-policy changes, real-data operations, commits, integration, remote operations, and releases.

If `CONTRIBUTING.md` exists, read it before repository maintenance.

Run `npm run check` after changes, `npm run check:full` and applicable browser acceptance before delivery or integration, and `npm run check:milestone` at milestones. Record missing or failed checks accurately. Preserve tests, assertions, and quality limits; obtain explicit approval before lowering policy or migrating protection for a removed requirement.

For module, state, or backend changes, read `docs/architecture.md`. Parse external data at adapters, keep pure logic independent of UI and transport, and use feature public entries. For concurrent work, follow `docs/collaboration.md`: separate worktrees and one writer per file, contract, and lockfile.

Use synthetic fixtures and independent source, server, browser, and output locations. Verify the actual built artifact and running server. Wait for explicit asynchronous completion; query the original operation before retrying an unknown result.

Use a new, independent reviewer session for nontrivial work. Follow `docs/verification.md` and record the candidate, commands, exits, failures, evidence, and remaining acceptance in the task or review record. Store runtime logs and build output in the configured artifact directories. Keep guides focused on current usage and constraints.
