## 阻塞合入的问题

### R1 — P1：React TS6 丢失既有 React 规则

- **位置：** `tools/template-tests/src/assembly.ts:110-118`，`scaffold/presets/react/.oxlintrc.json:2-6`，两个 `templates/react-{npm,bun}-ts6/.oxlintrc.json`。
- **根因：** 已合并的预设配置被 TS6 公共 `.oxlintrc.json` 整体覆盖，React plugin 与 `rules-of-hooks`、`exhaustive-deps`、`jsx-no-target-blank` 被删除。违反方案 `:257` 及实现单的同等强度、不得削弱保护要求。
- **独立重放：** 在 C 的 `src/app/InvalidHooks.tsx` 注入下面组件，`react-hooks-tsc=0`、`react-hooks-ts6=0`；同文件使用默认 React 的 Oxlint 配置，`react-hooks-control=1`，明确报 `react-hooks(rules-of-hooks): React Hook "useState" is called conditionally`。探针已移除。

```tsx
import { useState } from 'react';
export function InvalidHooks({ enabled }: { enabled: boolean }) {
  if (enabled) {
    const [value] = useState(0);
    return <span>{value}</span>;
  }
  return null;
}
```

**建议：** 保留预设非类型规则，仅在组合后的配置中关闭 22 条类型规则；对 npm、Bun 的 React TS6 都保留可编译 Hooks 负例。

### R2 — P1：CI static 的 shell 表达式必败

- **位置：** `.github/workflows/template.yml:46-55`。
- **触发与输出：** 原样抽取第 54 行，并预先给 `expected` 赋 12 项；`ci-count-exact=2`，输出 `test: "12": integer expression expected`。YAML block 内的 `\"` 是字面 shell 转义，参数包含引号。
- **第二处独立问题：** expected 为 registry 原序，actual 却排序；`ci-order-negative=1`，两序列断言不等。只修引号仍不能通过 diff。
- **影响：** pairwise-static、bun-risk-full、defaults-milestone 都依赖 static，会被一起跳过。
- **建议：** 使用正常 shell 引号，双方一致排序，完整重放此步骤。

### R3 — P1：G 跨平台 job 在 Bun 成品里先跑 npm ci

- **位置：** `.github/workflows/template.yml:169-178`。
- **重放：** 在只含该成品真实 manifest、bun.lock、.npmrc 的独立目录执行 `npm ci --offline`，`ci-G-npm-ci=1`，`EUSAGE`：需要已有 `package-lock.json`。网络恢复也不会修复缺锁。
- **影响：** 即使 static 修复，macOS/Windows 的 G 仍无法进入 Bun frozen / full。
- **建议：** 先以锁定 Bun 安装，再用同一依赖树的 Playwright CLI；按操作系统选择浏览器安装参数。没有实测的宿主部分仍记 not_run，不宣称已验跨平台。

### R4 — P1：约定矩阵与原契约门禁未完整迁移

- **位置：** `.github/workflows/template.yml:60-89,180-209`，`tools/template-tests/tests/generation.test.ts:467-480`，`tools/template-tests/package.json:23-25`；对比 main 的 template workflow 原 `npm run check --prefix tools/template-tests`。
- **实际：** pairwise-static 仅检查目录和 manifest 存在；没有方案 `:208-209` 的六个 Ubuntu `options-full` job，也没有三默认×三 OS 的 `defaults-full`。defaults-milestone 只有三个 Ubuntu 成品的正向 milestone。
- **保护回退：** 原 generation 契约中的错误模型、继承架构/lint、无名按钮、Vue 派生状态/值类型负例虽然文件仍在，却不被任何新维护 workflow 调用；正向成品 milestone 不会调用这些负例。`generation.test.ts:1-7` 还把不存在的 options-full 写成已调度。
- **建议：** 补足批准矩阵，并让原行为负例有等效的 CI 执行入口；保持批准的 milestone 抽样范围，不用全量扩张掩盖缺失调度。缺失保护须修复，不能用“以后测 timeout”延期。

### R5 — P1：TS6 到期阻断没有维护入口

- **位置：** `scaffold/common/tools/checks/toolchain.ts:26-27`，`ts6-review.ts:40-52,64-74`，两份 workflow；依据方案 `:124-130,177,212`。

- **建议：** 接入每天和手动维护检查，读取同一权威日期，在 `now >= reviewBy` 时非零；同时保留成品仅警告的行为及 Nika 批准延期条件。

### R7 — P1：npm audit 错误 JSON 被当成零高危放行

- **位置：** `tools/template-tests/src/locks.ts:76-97`；依据方案 `:172` 的“缺网络、报告不完整均不算通过”以及实现单依赖门。
